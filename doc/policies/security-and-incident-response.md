# 情報セキュリティ・インシデント対応規程（内部）

> リーガルレビュー（2026-09-21）反映済み。【要記入】を確定して施行する。

版：0.1

技術的な措置の詳細は design.md、requirements.md §10 を正とする。本規程は運用上の義務を定める。

## 1. 基本方針

- データの完全性（統計汚染の防止）も守るべき資産に含める。
- 費用の上限を可用性より優先する。過負荷時は止めることを許容する（requirements NFR-AVL-01）。

## 2. 暗号化

| 対象 | 措置 |
|---|---|
| 通信 | HTTPS のみ。HSTS を設定する |
| 保存データ | Supabase の保存時暗号化【要確認】 |
| パスワード | Supabase Auth がハッシュ化して保存する。当方は平文を扱わない |

## 3. 資格情報と権限

1. Secret は Git に保存しない。Render の環境変数、Supabase のダッシュボードで管理する。
2. 本番と開発の資格情報を分離する。開発用のテストユーザー（`*@isobath.local`）は本番で無効（`ALLOW_TEST_USERS=false`）とする。
3. 管理画面（Supabase、Render、Cloudflare、GitHub）は MFA を必須とする。
4. 権限の付与・剥奪を記録し、四半期ごとに棚卸しする。

## 4. ログ

1. ログに JWT、Refresh Token、Authorization ヘッダ、パスワード、Secret、回答内容、メールアドレスを記録しない（requirements SEC-LOG-01）。
2. 利用者はハッシュ化した識別子（`user_hash`）で記録する。
3. 保持期間：【要記入】

## 5. バックアップ

1. Supabase のバックアップ機能を用いる。保持期間：【要記入】
2. 復元手順を【要記入：頻度】ごとに検証する。
3. 削除済み利用者のデータがバックアップ経由で復元された場合は、復元作業の一部として tombstone に基づき直ちに再削除し、再削除の完了を記録する。

## 6. 脆弱性対応

1. 依存関係はロックファイルで固定し（pnpm-lock.yaml、uv.lock）、月1回更新と脆弱性スキャンを行う。
2. 重大な脆弱性（CVSS 9.0 以上、または認証・認可に関わるもの）は【要記入：72時間】以内に対応する。
3. 【要記入：脆弱性の報告窓口（security.txt 等）】

## 7. 監視

requirements NFR-OBS-01/02 の指標を監視する。特に次を異常の兆候とする。

- 401 / 403 / 429 の急増
- 新規登録数・回答数の急変（Sybil 攻撃・統計汚染の兆候）
- 品質フラグの発生率の急変

## 8. インシデント対応

### 8.1 対象

個人データの漏えい・滅失・毀損、またはそのおそれがある事態。不正アクセス、誤送信、設定ミスによる公開、委託先での事故を含む。統計データの大規模な汚染も本手順に準じて扱う。

### 8.2 手順

| 段階 | 内容 | 担当 |
|---|---|---|
| 1. 検知・報告 | 発見者は直ちに個人情報保護責任者へ報告する | 全員 |
| 2. 初動・封じ込め | 被害拡大の防止（Emergency Mode の段階引き上げ、資格情報の失効・再発行、該当機能の停止） | 開発・運用担当 |
| 3. 調査 | 影響範囲（対象者数、データ項目、期間）、原因の特定。ログと audit_events を保全する | 開発・運用担当 |
| 4. 報告の要否判断 | 個人情報保護法の報告対象事態に該当するかを判断する | 個人情報保護責任者 |
| 5. 当局への報告 | 該当する場合、個人情報保護委員会へ報告する。**速報**：事態を知った時点から速やかに（目安として概ね3〜5日以内）。**確報**：原則30日以内、不正の目的をもって行われたおそれがある事態は60日以内（個人情報保護法第26条、同法施行規則第7条・第8条） | 個人情報保護責任者 |
| 6. 本人への通知 | 該当する場合、影響を受けた本人に通知する。困難な場合は公表等の代替措置 | 個人情報保護責任者 |
| 7. 再発防止 | 原因の対策、本規程・設計の見直し | 全員 |

### 8.3 報告対象事態（個人情報保護法施行規則第7条）

- 要配慮個人情報の漏えい等（本サービスは原則として取得しない）
- 不正に利用されることにより財産的被害が生じるおそれがあるもの
- 不正の目的をもって行われたおそれがあるもの（不正アクセス等）
- 1,000人を超える漏えい等

### 8.4 記録

インシデントごとに、発生・発見日時、経緯、影響範囲、対応、報告・通知の有無と日時を記録し、【要記入】年保存する。
