# Item Set 0.2 — 公開前レビュー用候補

> **未承認・未検証。本番の出題セットには切り替えていません。** 質問内容のレビューとパイロット調査を経て採否を決めます。既存尺度からの転載ではなく、`observation-domains.md` の設計区分から作成した案です。

## 構成

- 人格項目230問：共通アンカー30問＋10ブロック×20問。品質確認8問。計238問。
- 初回：アンカー30問＋無作為に選ぶ3ブロック60問＋品質確認8問＝98問。
- 全ブロックにD01〜D16を含み、各ブロックでは4領域が2問、12領域が1問。どの3ブロックを選んでも全領域を観測します。
- アンカーはD11・D13が1問、その他が2問。異なる観点を選び、単純な正逆の対を共通項目にしない方針です。
- 各領域の半数を逆方向に記述。極性は設計上の仮置きであり、領域を因子や合算得点として扱う根拠ではありません。
- 1人へのブロック選択率は3/10。ブロック同士の共回答率は1/15。既存の`bibd-uniform@1`で順序を無作為化します。
- 全員出題の品質確認は注意確認2問とアンカーの再質問6問。`quality_rule.of`は必ず共通アンカーを参照します。
- 旧0.1の10問（ID 1001〜1010）は一切変更していません。0.2は別のID・コードを使用し、旧版との座標比較やlinkingを主張しません。

## 公開前の確認事項

- 文の分かりやすさ、二重質問、回答しにくい状況、回答の望ましさの偏りを人手で確認。認知インタビューを行い、必要なら再作成。
- D02の協調・主張・対立の保持、D08の回復行動と回復速度など、領域内の異なる観点を一つの得点へまとめない。
- D04/D05/D10、D06/D11/D13、D07/D08/D09、D03/D14/D15の境界を特に確認。
- D10の金銭・疲労・評判の表現が生活条件に依存しすぎないか、D11の仮定が読み取れるかを確認。
- 正逆の類似項目を候補として含む。パイロット後に冗長性・方法効果・天井床効果を検証し、項目を絞る。
- アンカーの選定は内容上の仮説であり、分布・負荷・再検査信頼性で未検証。全員への出題が適切か確認する。
- 品質確認の再質問は文面を少し変えている。差が生じる理由を確認し、不一致だけで参加者を不正と断定しない。現行出題のランダム化は原項目との最小間隔を保証しない。
- `screening=normal`は対象外の機微な内容を含めないよう作成したという分類であり、専門家の承認を示さない。各行のnoteは未承認と明示。
- 以下の機械チェックは割当の構造を確認するだけで、妥当性・信頼性を認定しない。

## 検証と有効化

リポジトリルートで、DBへ接続せずに検証：

```powershell
python -m uv --directory app run python -m isobath.items --check-source --version 0.2 items/drafts/items-0.2.csv
```

通常の`python -m isobath.items`は直下の`items/items-*.csv`のみを読むため、本ドラフトは自動投入されません。承認後に対象CSVを明示してバッチロールで投入し、DBの`--check --version 0.2`に通ることを確認してから、`ITEM_SET_VERSION`とモデル成果物の項目セットを整合させて公開します。既存回答のID・文面・割当を上書きしません。
